# Sight scales: what the overlay draws and where each number comes from

Audit of 2026-11-05 against the Squad dedicated server package (build 26005357). Russian version: [sight-scales.ru.md](sight-scales.ru.md). Labels: **VERIFIED** (read from the game files, reproduced by a test), **COMPUTED** (physics from verified inputs), **ASSUMED** (not in the server files; the reason is given), **MEASURED** (the owner's in-game data, not in the repository). `tests/test_sight_scales.py` pins the constants this page changed; the weapon data are checked by `tests/test_game_weapons.py` and `tests/test_sight_data.py` (see [sight-data.md](sight-data.md)).

| Scale | What it is | Source | Label | Against the game |
|---|---|---|---|---|
| Mark (vertical offset) | `focal * tan(angle - bore)` below the centre, `focal = (width / 2) / tan(FOV / 2)` (`ballistics.screen_offset`, `mark_offset`) | the FOV you type, the screen, the weapon's flight | COMPUTED | rectilinear projection with a horizontal FOV; checked pixel by pixel against an independent integrator (`tests/test_mark_end_to_end.py`) |
| Zoom (FOV divisor) per view | the sight's FOV is `FOV / zoom` (`Weapon.sight_view`) | `ZoomLevels` of the closed turret, `SetFieldOfView(FOV / k)` in the weapon's `BlueprintOnZoom` (`tools/game_weapons.py`) | VERIFIED for emplaced and vehicle weapons; ASSUMED (x1) for hand-held launchers | the same as the game for the 38 entries that have a zoom; hand-held: see below |
| Bore | degrees the shot leaves above the view's centre: the barrel socket's pitch against the camera's | `Attach_Muzzle` socket, skeleton reference pose and camera components (`tools/game_weapons.py`) | VERIFIED for emplaced and vehicle weapons; ASSUMED 0 for hand-held launchers | `docs/sight-data.md` lists every entry and every missing piece |
| Launch point | pivot height, muzzle forward and up | vehicle seat entries, wheel contact, socket | VERIFIED where the files give it; the rest is listed in `sight-data.md` | -- |
| Range ladder: ticks | the mark offset of a flat-ground target at 25 to 1000 m steps | `ballistics.range_ladder` | COMPUTED | follows the mark; the step set (25, 50, 100, 200, 250, 500, 1000) is a display choice, not game data |
| Range ladder: greatest distance | `LADDER_MAX_DISTANCE` | the game's play areas: `SQMapBoundary.XYBoundary` spline of each map | VERIFIED (data), constant changed 5000 -> 8000 m | the old comment said no map is longer than 5000 m diagonally; 9 of the 17 maps measured are (Yehorivka 7043 m, Skorpo 6503, Sanxian 6425, BlackCoast 5877, Tallil 5803, Manicouagan 5664, Harju 5582, GooseBay 5566, Gorodok 5322; `tests/data/play_areas.json`) |
| Mil scale | 6400 mils per circle (`MILS_PER_DEGREE = 6400 / 360`) | `UMG_Mortar_Firetable` names the unit "MILLIRADIAN (mil)"; the earlier reading of the mortar control's formula `floor((90 - 0.5 asin(...)) * 17.78)` is quoted in `docs/aiming.md` (its disassembly is no longer on disk) | VERIFIED (unit name), the formula UNVERIFIED now | 17.78 against 6400 / 360 = 17.7778: 0.012 %, 0.2 mil at 1500 mil, far below the mortar's spread |
| Mortar firetable range | the game's table lists 50 m steps up to 1250 m | `UMG_MortarControl` `DistanceToCover` 1250, `IncrementDistance` 50 | VERIFIED | our mortar reaches 1236 m (110 m/s, g 9.80): inside the table |
| Mortar sight limits | 45 to 88.875 degrees (`elevation_limits`, `hold_elevation`) | the mount's `PitchInterval` is 0 to 43.8 relative to the tube's rest; 45 + 43.8 = 88.8 | ASSUMED: 88.875 is the top reading seen on the sight (one key step of 0.075 degrees above), the rest pitch is not in the files | 0.075 degrees = 0.07 m of range, ignored |
| AGS-17 hold rate | 9 degrees per second of key hold | keyboard pitch x 15 x turret input x 0.6 from the input config | VERIFIED rate; the hold time model (top, speed) MEASURED | 67 measurements of the owner (279 to 1931 m) |
| Reticle marks of the sights (mil dots, range marks) | not drawn: the overlay has its own mark | reticle widgets and textures (`Vehicles/*/Reticles`, `UI/Widgets/Vehicles/Mortar/Mortar_reticle`) | UNVERIFIABLE | the server package keeps the widget layout and the texture metadata (for example `mortar_reticle` 2048 x 2048) but no pixels (two `.ubulk` files in 88727 entries); the files hold no `ZeroingRange`, `RangeMarkings` or mil-scale numbers, only `DefaultZeroingText` display strings such as "100m" on machine guns |

## Differences found

1. **Ladder limit (fixed).** `LADDER_MAX_DISTANCE` was 5000 m with the comment "no Squad map is wider than 5000 m diagonally across its play area". The game's boundaries measure up to 7043 m corner to corner, so a tank gun or an MK19 had no tick past 5 km on the larger maps. The limit is 8000 m now; `mark_visible_range` uses the same limit for "on screen to the search limit".
2. **Hand-held ADS FOV (open, deadline-squad/squad-ballistics#17).** `SeparateAdsFov` of the hand-held launchers (RPG-7V1 61, RPG-28 37, C90-CR 69, Carl Gustav 77, MAAWS 60, NLAW 70, RPG-29 optic 49, the UGLs 80 to 90) is in the game files, but whether it replaces or scales the FOV setting is native code; the overlay keeps its x1 assumption until one in-game measurement settles it.
3. **Mortar top elevation.** 88.875 degrees against 45 + 43.8 = 88.8 from the mount: a 0.075 degree step, not used.

Nothing else differs: zoom, bore and launch point agree with the files for all 78 emplaced and vehicle entries (`tests/test_game_weapons.py`, `tests/test_sight_data.py`).
