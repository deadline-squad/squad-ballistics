# Руководство по прицеливанию: Squad Ballistics и Deadline SquadCalc

Как добиться максимальной точности с оверлейной меткой, шкалой дальностей и картой SquadCalc, для каждого оружия отдельно. English version: [aiming.md](aiming.md).

Рамки: Linux, X11 или XWayland, экран 16:9 (1920x1080 или 2560x1440), FOV игры 120, ровная местность, если в разделе не сказано иное. Метка - тонкий красный крест, 50 px в поперечнике и 1 px толщиной (настроек стиля, цвета и размера у неё нет); *Align with the sight* и шкала дальностей остаются. Боковая кнопка мыши **Mouse4**, которая переключает выбранное оружие между записями `· optic (RMB ×N)` и `· no optic`, уже в `dev` (клавиша по умолчанию, меняется в настройках горячих клавиш).

## Как читать это руководство

У каждого числа есть тег источника. **V** = проверено: прочитано в коде или игровых данных, либо воспроизведено тестом или скриптом. **C** = вычислено одноразовым скриптом из входных данных V (модель описана в разделе 5; скрипта в репозитории нет). **A** = предположено или выведено; тест, который это решает, назван. Там, где поведение игры неизвестно, в тексте сказано "unknown, test X".

| Тег | Источник |
|---|---|
| `B` | `ballistics.py` (`mark_offset`, `mark_resolution`, `mark_visible_range`, `range_ladder`) |
| `Cr` / `Cf` | `crosshair.py` (`marker_notes`, шаги инструкции "как стрелять") / `config.py` |
| `README` / `RN` | `README.md` / `RELEASE_NOTES.md` (1.6.0) |
| `T-aids`, `T-e2e` | `tests/test_marker_aids.py`, `tests/test_mark_end_to_end.py` (независимый эталон `tests/flight.py`) |

## 1. Десять правил

1. **Два вида оружия, два вида точности.** *Осколочное (splash)* оружие (подствольные гранатомёты, MK19, AGS-17/30, QLZ87, SPG-9 FRAG, Grom FRAG) попадает или промахивается по *дальности на земле* точки разрыва, поэтому важно число "1 px = N м дальности". Оружие *прямого попадания (direct-hit)* (снаряды HEAT/AP: RPG-7, PF98, AT-4, SMAW, MAAWS, Carl Gustav, SPG-9 HEAT, орудия танков и ZiS-3) попадает или промахивается по *высоте у цели*; там один пиксель стоит `N м x tan(угол снижения)`, то есть 0.1-1.8 м на 300-1000 м (раздел 5.2), а не десятки метров. Не считайте "1 px = 39 m" на танковой пушке провалом. `C`
2. **Прицеливание по маркеру честно работает для:** оптики AGS-17, AGS-30 (BTR-4, BMP-1TS) и оптики QLZ87 (1.3-2.8 м на пиксель при FOV 120), прицела SPG-9 (5.2 м, но это оружие прямого попадания, поэтому вертикальная ошибка 0.1-0.3 м) и любого оружия прямого попадания из таблицы выше, если точку прицеливания поднять к середине цели. Виды без увеличения для осколочного оружия (MK19 19-20 м/px, QLZ87 *no optic* 13 м/px, AGS-17 *no optic* 5-7 м/px) можно навести на маркер на земле, но один пиксель там уже стоит больше радиуса разрыва: используйте их только для огня по площади. `V` (разрешение) / `C` (вердикт)
3. **Центр метки можно поставить с точностью до долей пикселя; рука так не сможет.** Крест рисуется в своей дробной позиции, ошибка центра 0.02 px (`T-aids`, `T-e2e`). Предел задают шаг мыши (раздел 3) и глаз: закладывайте +-1 px, в лучшем случае +-0.5 px.
4. **Снизьте чувствительность мыши в игре для прицельных видов.** Когда ползунок Global, умноженный на ползунок данного зума, равен 1, один отсчёт мыши даёт 2.3 px без зума и 3.5-3.7 px в оптике (раздел 3.2), то есть 3.5 px x 1.7 м = 6 м дальности на отсчёт в оптике AGS-17. Стремитесь к не более чем 1 px на отсчёт (произведение ползунков около 0.25 при 1080p). `A` (константа движка 0.07, на которой это основано, не подтверждена, тест 7.6)
5. **Ошибка положения, которая важна в режиме маркера, - это ошибка дальности** (ваша позиция и позиция цели, отмеченная на карте: сигма = sqrt(2) x ошибка одного клика). Азимут не важен, его даёт маркер. Ставьте обе точки при масштабе карты 6 или крупнее (0.25 м на пиксель экрана на карте 4 км) на ориентир, который виден и в игре. `V`
6. **Поднимайте точку прицеливания для оружия прямого попадания.** Игровой маркер - это трассировка на землю (рельеф, но никогда не крыша или дерево, `#6-6`), поэтому прицеливание по нему отправляет половину выстрелов под технику. Задайте `target_height` (`config.json`, 0-10 м, пока без UI) около 1.2 м. На 600 м при идеальных входных данных это поднимает шанс попадания в коробку 3.6 x 2.4 м примерно с 50 % до 100 % для PF98, AT-4 и прицела SPG-9; при типичных ошибках с 49 % до 71 / 72 / 100 % (раздел 5.3). `C` / `Cf`
7. **Калибровать стрельбой нечего.** В приложении нет поправки (trim) и другой полевой коррекции: FOV вводите вы (он должен совпадать с FOV игры), остальное из данных игры, поэтому промах нигде не вводится. Задаётся только *Align with the sight* (где метка стоит на экране, раздел 4.3). `Cf`
8. **Вспышка маркера короткая.** Дальше 60 м иконка в мире полностью видна только около 0.5 с, а при зуме имеет непрозрачность 20 % (`#6-6`). Заранее поверните на азимут и заранее выставьте тангаж, чтобы маркер появился в пределах 3-5 px от метки. `V` (файл) / `A` (как выглядит в игре: unknown, test 7.1)
9. **Клавиши - для грубых движений, мышь - для последнего пикселя.** Зажатая клавиша поворачивает с постоянной скоростью без разгона (тренога MK19/QLZ87/SPG-9: 66 град/с по тангажу, 120 град/с по рысканью; AGS-17: 9 и 18 град/с). Один кадр при 60 fps клавиши тангажа AGS-17 - это 0.15 град = 5.6 px в его оптике. `V` (`NR` 6, `GD`)
10. **Удерживайте Focus (задержка дыхания) на ручных гранатомётах.** Игра сужает FOV до двух третей (`README`); цена пикселя при таком FOV уменьшается вдвое (раздел 3.3), но программа считает метку для введённого вами FOV и на ручных гранатомётах за Focus не следует, поэтому там её метка при удержании Focus неверна (на обычных видах открытых башен и треног она за клавишей следует, раздел 3.5); шаг мыши тоже уменьшается вместе с FOV. Данные о раскачке есть только для ручных гранатомётов, и лёжа в 4 раза устойчивее, чем стоя (12 / 7 / 3 для стоя / присев / лёжа, единицы неизвестны). `V` (данные) / `A` (Focus на стационарном оружии: unknown, test 7.4)

## 2. Сколько стоит один пиксель (вопрос 1)

### 2.1 Определение и масштабирование

`mark_resolution` (`B`) берёт углы возвышения, при которых снаряд падает на 1 м по обе стороны от цели, переносит их на экран относительно линии визирования на цель и возвращает `1 / slope` (метры дальности на пиксель строки метки). От разрешения оно не зависит, кроме как через фокусное расстояние `f = (W/2) / tan(view_FOV/2)`: **значение для 1440p ровно в 0.75 раза меньше значения для 1080p** для любого оружия и дальности (проверено на 13 видах оружия x 4 дальностях x 2 разрешениях: отношение 0.7500-0.7500; относительно независимого эталона `tests/flight.py` в пределах 2 % в 100 из 104 случаев, худший 3.5 % на 100 м для PF98 и T-64BM2, где конечный полупиксельный шаг груб; `V`, `T-aids` повторяет это для 1080p).

Зум прицела делит FOV (`Weapon.sight_view`, `B`), выстрел уходит на `bore` градусов выше центра экрана, а масштаб *Align with the sight* `s` (50-150 %, целые проценты) умножает все смещения, поэтому пиксель стоит `m/px / s` (`T-aids`). Строки ниже приведены при масштабе 100 %.

### 2.3 Наименьший шаг, максимальная дальность на экране, рейтинг

- **Наименьший шаг.** Метка движется целыми пикселями экрана лишь в том смысле, что маркер можно совместить с ней с точностью +-1 px; сама метка рисуется в дробной позиции (0.02 px). Шаги настроек: смещения *Align* 1 px, масштаб 1 % (на расстоянии 500 px ниже центра это 5 px). `V` (`Cf` `RANGES`)
- **Максимальная дальность на экране при FOV 120, 1080p.** Оптика AGS-17 940 м (1440p: 943 м), оптика QLZ87 1490 м (1502 м), AGS-30 BTR-4 1590 м, прицел SPG-9 FRAG 1960 м, прицел SPG-9 HEAT 3400 м; виды без зума остаются на экране до своей досягаемости или дальше. За этим пределом информационная строка пишет "mark off screen past N m", а стрелка у края остаётся. Предел лишь слабо зависит от разрешения, потому что отступ экрана фиксирован и равен 20 px. `V` (`T-aids`: 940 и 1490 против эталона)
- **Рейтинг по метрам дальности на пиксель (лучшие первыми), FOV 120, 600 м** (подствольные и ружейные гранаты дают 1.3-2.2 м/px в пределах своей досягаемости 500-620 м и в рейтинг не включены): оптика AGS-17 1.7 < оптика QLZ87 = оптика AGS-30 2.7 < оптика SPG-9 FRAG 3.0 < оптика SPG-9 HEAT 5.2 < 2A70 FRAG 5.9 < AGS-17 iron / no optic 6.5 < M72 LAW 7.2 < TBG-7V 8.1 < Grom FRAG 9.3 < QLZ87 no optic 13 < оптика ZiS-3 14 < SMAW / PF98 HE-I 18 < RPG-7 / MAAWS 19-20 < MK19 19-20 < Carl Gustav 20-35 < AT-4 31 < SPG-9 без оптики 33 < PF98 Tandem 36 < танковый AP 39-212 < ZiS-3 без оптики 90. `V`
- **Какой вид можно честно наводить на маркер.** Критерий: пиксель (+-1 px прицеливания) стоит меньше собственного разброса оружия по дальности (раздел 5.3, `sd`) и меньше 5 м, которые использует `MARK_PIXEL_LIMIT` (`B`).

## 3. Мышь и настройки игры (вопрос 2)

### 3.1 Что игра делает с отсчётами мыши

Источник: `GD` (`/tmp/mech/ini/*`, `IMC_*.uasset.json`, декомпилированные модификаторы, `GameSettingsWindow.uasset.json`). Всё `V`, если не отмечено иное.

- Действие обзора `IA_Look` на `Mouse2D` проходит модификаторы **FOVScaling -> Negate (Y) -> Sensitivity -> InvertAxis** в контекстах солдата, солдата на установке и башни (танк, IFV, тренога, миномётчик). FOVScaling равен `value x 0.01111 x camera_FOV`: ровно 1.0 при FOV 90, 1.333 при 120 и *пропорционален текущему FOV камеры* (меньше в виде с зумом). Сглаживание и кривая отклика есть только в контексте водителя.
- Модификатор Sensitivity умножает на пользовательский ползунок **Global**. Контроллер игрока умножает ещё раз на `InputYawScale = 2.5`, а затем на `CurrentSens`, который берётся из *ползунков по состояниям*: стрельба от бедра (**Point shooting**), а при зуме карта **Soldier 1x / 2x / 3x / 4x / 5-6x / 7-9x / 10x+** (ключ = увеличение оптики; берётся ближайший ключ), для башен и техники карта **Vehicle 1x / 4x** (ключ = FOV по умолчанию / текущий FOV камеры). **Steady Aim** (задержка дыхания) умножает поверх при прицеливании (ADS). Диапазоны ползунков: Global, Point shooting, Vehicle 0.01-4.0; ползунки по зумам 0.01-2.0. Значения по умолчанию лежат в нативном коде, **в данных их нет: читайте их в своих настройках**.
- Конфигурация осей движка: чувствительность 0.07 на отсчёт, показатель степени 1, мёртвой зоны нет, сглаживание мыши выключено, масштабирование по FOV включено. **В игре нет ни опции сырого ввода, ни опции ускорения мыши**; доставляет ли путь Proton/XWayland сырое или ускоренное движение, неизвестно (тест 3.4).
- На отсчёт при FOV камеры `F` градусов: `deg = k x G x S x F / 90`, где `k = 2.5 x 0.07 = 0.175` **если** 0.07 из движка доходит до действия обзора (`A`; иначе k = 2.5), `G` - ползунок Global, `S` - активный коэффициент состояния. Перевод в пиксели использует ту же проекцию, что и метка: `px = deg x (W/2) / tan(F/2) x pi/180`.

### 3.5 Focus на открытых башнях и треногах

`V` (байткод `BP_GenericVehicleOpenTurret` и `BP_GenericDeployableTripodVehicle`, `tools/game_weapons.py`). Пока удерживается Focus (`IA_Focus`), общая открытая башня плавно меняет FOV у `Camera1pComponent` до 0.666 от настройки (`AllowFocus`, у общей открытой башни true), а общая тренога так же меняет `FirstPersonDriverCamera` (`bAllowFocus`, которое общая тренога оставляет false: тренога MK19, АГС-17 с открытым прицелом, СПГ-9 и M2 ставят true). Башни QLZ87 на CSK131, WZ551 и ZBL-08, СПГ-9 на техничке, тренога АГС-17 с оптикой и тренога СПГ-9 с прицелом ставят false, а у треног QLZ87 и ЗиС-3 параметр не задан вовсе: они не реагируют. Обычный вид тогда крупнее в 1 / 0.666 = 1.502 раза, и метка, рассчитанная на полный FOV, ложится далеко за целью (аудит техники насчитал несколько сотен метров на 1000 м у АГС-17).

Программа отмечает такие виды в `weapons.json` (`focus_narrows_view`, сверка с файлами игры в `tests/test_vehicle_zoom_views.py`) и следует за клавишей: Focus по умолчанию — **Left Shift** (`Content/Input/IMC_Turret`, `IMC_GroundVehicle` и `IMC_MountedSoldier`, `DefaultKeyMappings`); она читается так же, как S и W у АГС-17 (`keystate`, evdev или X11). Метка, шкала дальности и заметки о пикселе переключаются сразу, когда клавиша нажата или отпущена; игра меняет FOV не мгновенно, поэтому на миг метка опережает картинку. Строка оверлея пишет «The mark follows Focus (Left Shift).» или, если клавиши не читаются, «The mark assumes Focus (Left Shift) is not held.» Focus, назначенный в игре на другую клавишу, не читается (`IA_Focus` переназначаемое действие; файла, где игра хранит переназначения, у нас не было), а Left Shift, нажатый ради другого, при выбранной такой записи сужает метку ошибочно.

Что картинка, по которой целится игрок, — тот самый компонент, который двигает перелив, — **гипотеза**: байткод проверен, показанный эффект нужно подтвердить выстрелом в игре (тест 7.4).

## 4. Процедуры (вопрос 3)

Общая подготовка (один раз за сессию): Linux-композитор включён, игра в окне без рамки или в полноэкранном режиме 16:9, **поле FOV равно FOV игры** (ползунок FOV в настройках игры; SB его из игры не читает; под Focus метка неверна на ручных гранатомётах и следует за клавишей у записей, где это отмечено, раздел 3.5), запись оружия соответствует виду (удерживаемая RMB = `· optic`, не удерживаемая = `· no optic`; Mouse4 переключает), оверлей включён (F8). Шаги "How to fire" на странице Calculator и информационная строка говорят то же самое для выбранного вами оружия (`Cr`).

**Экран настраивать не нужно.** SB находит окно самой игры на X-сервере (`WM_CLASS` `steam_app_393380`, который ему даёт Proton, или заголовок `SquadGame`) и рассчитывает метку на ширину этого окна: в окне, без рамки, на весь экран, на любом мониторе или в более низком режиме игры, который композитор растягивает на экран. Оверлей следует за окном, когда его двигают или меняют размер, и снова накрывает выбранный в настройках монитор, когда игра закрыта или окно не найдено. Предупреждение остаётся только для окна не 16:9. Метка точна лишь настолько, насколько точен введённый вами FOV, поэтому держите его равным FOV в настройках игры. При FOV не 90 напечатанные в игре метки дальности на сетке прицела (оптика, прицелы наводчика, гранатомёты) уже не совпадают с меткой (при FOV 120 напечатанная метка 500 м оптики QLZ87 ложится около 650 м, примерно на 30 % дальше; см. «Метки сеток прицелов игры» в `sight-data.ru.md`), поэтому информационная строка велит наводить на цель метку SB, а не напечатанные метки. `V` (код и тесты; класс и заголовок окна - `A`: не сверены с живым окном Proton)

### 4.1 (a) Прямой огонь с помощью маркера

Цель: уложиться в числа раздела 5.3. Для каждого шага названа ошибка, которую он убирает или добавляет.

1. **Собственная позиция.** Поставьте точку оружия на карте SquadCalc при масштабе 6+ на ориентир, который виден и в игре (перекрёсток дорог, угол здания), или введите кейпад своего места (раздел 4.6). Ошибка 1-3 м. `V`/`A`
2. **Позиция цели.** Маркер стоит на настоящей цели; отметьте то же место на карте SquadCalc (флаг цели) при масштабе 6+. Метка вычисляется для расстояния между двумя кликами; при включённом `map_follow` расстояние и разность высот сразу попадают в калькулятор (`README`). Теперь калькулятор показывает расстояние, разность высот и метку.
3. **Высота.** Карта даёт высоты (билинейно, сетка 1 м, `SC`); ошибка высоты в 1 м стоит 0.00-0.28 м дальности в режиме маркера (`C`, раздел 4.5), игнорируйте её, если цель не на крыше или вершине дерева (игровой маркер лежит на земле под ней).
4. **Точка прицеливания.** Для оружия прямого попадания задайте `target_height` равным высоте середины техники (около 1.2-1.5 м). Для осколочного оружия оставьте 0.
5. **Предварительное наведение до появления маркера.** Повернитесь на азимут из SquadCalc по компасу (целые градусы; в виде миномёта показаны десятые) и приведите ствол примерно к тому тангажу, при котором метка лежала бы на рельефе (шкала дальностей, `README` шаг 4). Цель - чтобы вспышка маркера попала в пределы 3-5 px от метки: она полностью видна около 0.5 с дальше 60 м, а её альфа ограничена значением 0.2 при зуме (`#6-6`, `V` для данных файла, `A` для вида в игре).
6. **Совместите центр иконки маркера с центром креста и стреляйте.** Иконка имеет размер 46 px на 0 м и 24 px начиная с 50 м; это экранный виджет с центром в спроецированной точке (`#6-6`). Совпадает ли визуальный центр текстуры с центром пикселя, неизвестно, тест 7.1. Пользуйтесь мышью (чувствительность по 3.2), а не клавишами.
7. **Ожидаемый результат** (ошибка положения 1 м на клик, 1 px прицеливания): раздел 5.3. Не ждите, что попадут все выстрелы: один лишь разброс ограничивает попадание в 5 м значениями 42 % (MK19) и 84 % (оптика AGS-17).

### 4.2 (b) Известная цель на карте SquadCalc, без игрового маркера

Метка - это опора по тангажу над линией визирования на цель, поэтому в поле зрения нужна сама цель или опора для горизонта.

- **Цель в поле зрения:** поместите точку цели на земле на метку; карта цели и любой маркер не нужны (введите дальность или возьмите её с карты).
- **Цель вне поля зрения или за рельефом:** повернитесь на азимут с карты (калькулятор его показывает, 0.1 град в SquadCalc, целые градусы на игровом компасе: +-0.5 град - это +-2.6 / 5.2 / 8.7 м бокового отклонения на 300 / 600 / 1000 м; у компаса есть режим 0.1 град в виде миномёта, `GD`). Для тангажа на экране нет опоры, кроме видимой земли: поместите *видимую точку земли с известной дальностью на деление шкалы этой дальности* (шкала дальностей - это положение на экране для каждой дальности на ровной местности, `README`); камера моделируется в точке шарнира ствола (`B`, эталон `T-aids`), поэтому ошибка равна разности углов снижения двух точек земли, примерно `eye_height x (1/d1 - 1/d2)` рад (2 px при FOV 120 для 2 м, 300 м и 600 м, `A` для высоты глаза, тест 7.3). Считайте результат огнём по площади, а не выстрелом класса "маркер".
- Для **навесного огня AGS-17** наведением служит не метка, а время удержания S (`README`, 67 измеренных удержаний, остаток 5.5 м RMS при 9.00 град/с, `NR` 6).

### 4.3 (c) Выравнивание метки: *Align with the sight*

Назначение: убрать расхождение между местом метки на экране и вашим прицелом (выравнивание: где метка находится на экране). Делайте это на ровной местности на Training, никогда не на `squad1`.

1. **Подготовка.** Ровная горизонтальная местность, прямая линия 300 м (для оптики длиннее: 600 м). Измерьте расстояние на карте SquadCalc, обе точки при масштабе 6+ (ошибка около 0.5 м), или используйте два поставленных объекта. Запись оружия верна для вида, поле FOV равно FOV из настроек игры, `target_height` 0, выравнивание сброшено.
2. **Align with the sight** (страница Crosshair). Откройте прицел оружия в игре и сравните метку с сеткой прицела на нулевой дальности оружия, где метка должна лежать на нулевой линии сетки: оптика QLZ87 100 м, тренога MK19 330 м, прицел SPG-9 около 765 м (HEAT), открытый прицел AGS-17 около 300 м, ZiS-3 около 350 м (`README`, значения bore). Двигайте метку кнопками *Move left/right* и *Move up/down* (стрелки, шаг 1 px) на прицел. Точность: +-1 px на глаз, то есть метры одного пикселя (раздел 2.2): 1.7 м в оптике AGS-17, 2.8 м в оптике QLZ87, 5.2 м в прицеле SPG-9. Оставляйте *Scale* равным 100 %, если только две отметки сетки на разных дальностях обе не расходятся: масштаб задаётся целым процентом (5 px на расстоянии 500 px ниже центра, 8 м в оптике AGS-17).

### 4.4 (d) Миномёты, Hell Cannon, реактивная артиллерия

Метки нет. Угол берётся из калькулятора, а прицел - игровой.

- **Возвышение.** Прицел миномёта в милях, целые: одна миля - это 0.05625 град, 1.4-2.4 м дальности на 1000-300 м (шаг `SC`; `GD` `UMG_MortarControl`: `mil = floor((90 - 0.5 x asin(...)) x 17.78)`). HUD Hell Cannon показывает 0.1 град (3.0 м на 300 м, 2.5 м на 600 м). Расширенный виджет M121 показывает угол и азимут с точностью 0.1 град. Округление намного меньше разброса (миномёт 50 MOA 17 м, Hell Cannon 100 MOA 25 м на 300-600 м, `SC` ran), так что отображаемое разрешение не является пределом. В таблице игры **нет шага 0.5 мили**; автонаведение SB (F7) работает с точностью до 0.5 мили от показаний прицела (`sightlay.py` `TOLERANCE`).
- **Клавиши.** Ствол движется на 9.0 град/с при зажатой клавише, поэтому один кадр при 60 fps - это 0.15 град = 2.7 мили (4-6 м дальности): коротко нажимайте для грубой наводки, а потом используйте мышь (тангаж ствола ×0.03 от скорости обзора, `GD`/`A`: около 0.005 град = 0.09 мили на отсчёт при FOV 90 и G = S = 1) для последних миль.
- **Компас.** Целые градусы вне вида миномёта (1 град - это 5.2 / 10.5 / 17.5 м бокового отклонения на 300 / 600 / 1000 м), 0.1 град в виде миномёта (`NR` 5). Используйте десятые в виде миномёта для азимута и задавайте азимут по значению SquadCalc (0.1 град). При ошибке азимута 1 град боковое отклонение равно разбросу на 600 м: для миномётов это главный член, а не возвышение.
- **Разброс** для планирования: миномёт 81 мм 17-18 м в стороны на 100-600 м, 16 м на 1000 м; Hell Cannon 25-26 м на 300 м; UB-32 9-70 м в стороны и 150-350 м по дальности; BM-21 30-75 м в стороны (`SC` ran, `squadFiringSolution.js:247-300`).

### 4.5 (e) Возвышенные и пониженные цели, `target_height`

- Введите разность высот или возьмите её с карты (цель выше `+`). Метка вычисляется над *линией визирования* на цель, поэтому склоны обрабатывает приложение (`B` `solve`, `sight_angle`).
- Карта задаёт высоту цели по карте высот (билинейно, сетка 1 м, с точностью до сантиметра на рельефе: медиана 0.00 м относительно серверных маркеров, `#8`); крыши и верхушки деревьев дают ошибку 1-5 м на 2-8 % кликов (`#6-4`).
- **Режим маркера:** маркер лежит на рельефе, поэтому высота почти полностью убирается: ошибка высоты в 1 м стоит на 300 / 600 / 1000 м, MK19 0.03 / 0.05 / 0.09 м, оптика AGS-17 0.07 / 0.16 / 0.28 м, оптика QLZ87 0.04 / 0.08 / 0.14 м, PF98 / SPG-9 / танк менее 0.02 м (`C`).
- **Режим только вычислений (без маркера):** ошибка высоты в 1 м - это ошибка ствола 1/D рад: 0.19 / 0.096 / 0.058 град на 300 / 600 / 1000 м (`C`), то есть 36 / 18 / 10.7 м для MK19 и 12 / 6 / 3.6 м для AGS-17 (`#6-4`).
- `target_height` (только в конфигурации, 0-10 м, по умолчанию 0): целится на столько выше земли цели, метка смещается вниз, информационная строка показывает `aim +1.5 m`. Используйте ~1.2 м для середины техники, ~1 м для стоящего солдата с оружием прямого попадания, 0 для осколочного. Миномёты его игнорируют.

### 4.7 (g) Цель с карты против введённой дальности

- При включённом *Put the map target and weapon into the calculator* (`map_follow`, сборка Deadline) новейшая цель с карты заполняет расстояние и разность высот, а оружие синхронизируется в обе стороны (`README`). Ручной ввод расстояния перехватывает управление **до следующей цели с карты**; повторная доставка картой той же цели не перезаписывает введённые вами значения (`Cr` `last_map_target`).
- У введённого расстояния нет профиля рельефа, поэтому нет предупреждения о препятствии (`⛔`) и нет азимута. Цель с карты несёт профиль карты высот и азимут.
- **F9** очищает цель, введённое расстояние и цель с карты (но не выравнивание); новая цель с карты восстанавливает метку.
- Правило: используйте карту для первого, дальнего выстрела (азимут + проверка препятствий); вводите расстояние, когда корректируете по наблюдению (+25 м) или стреляете по видимой цели, расстояние до которой вы считали с дальномера; потом снова выберите цель на карте.

## 5. Бюджет ошибок (вопрос 4)

### 5.1 Модель

Одноразовый Монте-Карло (`C`; 1500 выстрелов на ячейку, фиксированный seed, чистый Python поверх `ballistics.solve`/`Weapon.flight_height`, в репозитории нет). Для каждого выстрела: цель находится на дальности D на ровной местности; дальность в калькуляторе равна `D + e`, `e ~ N(0, 2 sigma_pos^2)` (клик собственной позиции + клик цели); ствол равен `lambda_true + (theta(D_calc) - lambda_calc) + aim error`; ошибка прицеливания - это `sigma_aim` пикселей строки метки в проекции вида; конус: ошибка тангажа `phi cos psi`, ошибка рысканья `phi sin psi`, `phi` равномерна на `[0, MOA/120 deg]`, `psi` равномерна (`NR` 1). Попадание в землю: падение в пределах 5 м от точки прицеливания на земле (замена радиуса поражения для осколочных снарядов). Попадание в коробку: снаряд пересекает плоскость цели внутри коробки шириной 3.6 м x высотой 2.4 м, стоящей на земле (прицеливание в основание `L0` или на высоте 1.2 м `L1.2`). Камера в шарнире (параллакс реальной камеры, 0.23 м вверх и 0.34 м вправо на QLZ87, составляет -8.5 / -5.6 / -4.2 м на 200 / 300 / 400 м в обычном виде, `#5`, и в модель не входит). Сравнение с существующей моделью SquadCalc: эта модель (`hitProbability`, `squadDamage.js`) учитывает только разброс (без размера цели, без ошибки положения, `SC` ran) и в `dev` не содержит вероятности попадания при прямом огне (`#8` из `deadline-squadcalc`; работа лежит в незафиксированном worktree, и `tools/direct_fire/hit_probability_check.mjs` из-за этого падает на `dev` с `getHitSpread is not a function`). Столбцы "ideal" согласуются с `#6-2` (оптика AGS-17 84 %, оптика QLZ87 57 %, MK19 43 %).

Сценарии (сигма на клик положения / px прицеливания): **ideal** 0 / 0, **best** 1 / 0.5, **typical** 2 / 1, **poor** 3 / 3. В первом прогоне была и ошибка поправки (trim) (сигма 0 / 1 / 2 / 3 м дальности) как третий источник; в программе поправки больше нет, поэтому итоги в 5.2 - исходные без этого члена в квадратуре (`sqrt(total^2 - 2^2)`), а вероятности попадания в 5.3 его всё ещё включают.

Как это читать. (1) "Все выстрелы попадают" недостижимо для осколочного оружия: при непрерывной стрельбе 50 MOA MK19 ещё ниже (`#6-4`: шанс убийства одним выстрелом около 25 % для MK19 и QLZ87, 67-75 % для AGS-17). (2) P5 танкового орудия - артефакт плоскости земли (настильная траектория растягивает разброс вдоль земли): оценивайте оружие прямого попадания по столбцам Box. (3) Прицеливание в основание даёт в лучшем случае 50 %: поднимайте точку прицеливания. (4) В видах с зумом ошибка положения стоит мало (оптика AGS-17 83 -> 78 -> 66 %: от идеала до клика с ошибкой 2 м), а в видах без зума пиксель стоит всего (MK19 44 -> 17 %, AGS-17 iron 86 -> 46 %). (5) Перекрёстная проверка по разбросу SquadCalc (отдельный зонд на незафиксированном `getHitSpread`, идеальные условия): P5 на 300 м равно 0.18 для MK19 при 50 MOA (эта модель 17.5 %), 0.37 для танкового орудия (38 %), 0.84 для SPG-9 (84 %), 0.36 для RPG-7 HEAT при 20 MOA (35 %); обе модели согласуются в пределах 1-2 пунктов. SquadCalc не может показать ни один из важных здесь столбцов (ошибка положения, пиксель прицеливания, цель-коробка) - backlog 5-6. MK19 при непрерывной стрельбе (50 MOA) даёт 18 % на 300 м и 15 % на 1000 м.
